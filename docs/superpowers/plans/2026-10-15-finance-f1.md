# Finance F1 — service prices and invoices — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for
> tracking.

**Goal:** Clinics with the `finance` module can price services (base + per-doctor), issue gap-free numbered
invoices per branch from an appointment, a visit or by hand, edit/discount/void them under audit, print them
and send them to the patient by email or WhatsApp with a private link; the platform sees monthly totals only.

**Architecture:** A new `billing` API module (`apps/api/src/modules/billing`) on the medical-module pattern
(domain / ports / persistence / use-cases / http), one pure totals function in `packages/contracts` shared by
API, mock and print view, raw SQL migrations 0060–0063 with RLS + negative tests, the notifications ledger
extended for invoice sends, and the web screens built by Lovable from a brief once contracts are frozen.

**Tech Stack:** TypeScript, Zod (contracts), NestJS on Fastify, Drizzle + raw SQL (PostgreSQL 18, RLS),
vitest, TanStack Start + shadcn/ui (Lovable).

**Spec:** `docs/specs/finance-design.md` at `5f28618` — §3 (F1), §8 Review R1 and §8b Review R2 are
**binding**; where they differ, §8b wins over §8, and §8 wins over §3.

## Global Constraints

- Money is a `bigint` count of minor units; on the wire a decimal integer string (`"12500"`), never `number`
  (R1-2). One line ≤ 10¹² minor units.
- `total_minor = Σ line_total + tax_minor` (R1-1 step 6, fixed in `5f28618`); allocation per R2-1; worked
  examples E1–E6 are the acceptance table.
- Every clinic table: `clinic_id uuid NOT NULL`, PK `(clinic_id, id)`, RLS ENABLED + FORCED, policy
  `clinic_id = NULLIF(current_setting('app.clinic_id', true), '')::uuid` USING + WITH CHECK, indexes start with
  `clinic_id`, every FK indexed, no hard deletes, UUID v7 from the app (CLAUDE.md §5).
- New table ⇒ its RLS negative test in `db/tests/rls-isolation.sql` in the same PR.
- `eyadex_platform` has **no grant** on any finance table; it reads totals only through
  `finance_monthly_totals()` (FIN-3).
- Finance audit rows are `category = 'patient_access'`; snapshots hold ids, numbers and amounts, never patient
  names or free-line text (R1-3).
- Lock order for every money operation: per-clinic advisory lock (only for prices/currency/first issue) →
  patient row → invoice rows by id ascending; `If-Match` checked after the invoice lock (R2-8).
- Permissions are checked, never role names; guard order active user → clinic access → module (`finance`)
  → permission → branch scope (CLAUDE.md §6).
- Every UI string ar + en; «المراجع», never «المريض»; logical CSS only; files ≤ 300 lines; Arabic JSDoc on
  exported functions in `domain/**` and methods in `ports/**`.
- SQL files are forward-only: never edit an applied file. Production SQL needs the owner's explicit sentence.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Decisions taken while planning (orchestrator, flagged to the owner)

- **D-P1 "PDF" = the browser print view.** The API renders no PDF today (the prescription prints through a
  print view and `window.print()`). F1 follows that pattern: staff print or "Save as PDF" from a print view;
  the patient's `/i/<token>` link opens a public, print-ready invoice page. No server PDF library in F1.
- **D-P2 Spec wording fix:** §8b.4 says `0050_medical_release.sql` granted to the locked admin only; in fact it
  also granted doctor and receptionist keys. The finance decision is unchanged — the finance release grants to
  the locked clinic-admin role only — and Task 0 corrects the sentence.
- **D-P3 `BlobStore` moves to `apps/api/src/shared/blob/`** so the clinic logo can use it; medical keeps its
  behaviour (it imports the shared port). Logos are stored unencrypted (not patient data), max 1 MB, PNG/JPEG.

```ts
const BP = 10000n;
export function roundHalfUpDiv(n: bigint, d: bigint): bigint {
  return (n * 2n + d) / (2n * d);
}

function discountOf(base: bigint, d: Discount | null): bigint {
  if (d === null) return 0n;
  if (d.kind === "pct") {
    if (!Number.isInteger(d.bp) || d.bp < 0 || d.bp > 10000) throw new TotalsError("invalid_line");
    return roundHalfUpDiv(base * BigInt(d.bp), BP);
  }
  if (d.minor < 0n || d.minor > base) throw new TotalsError("discount_exceeds_total");
  return d.minor;
}

/** R1-1 + R2-1: the one totals function (API, mock and print view). */
export function computeInvoiceTotals(input: TotalsInput): Totals {
  const seen = new Set<number>();
  const sorted = [...input.lines].sort((a, b) => a.position - b.position);
  const lines = sorted.map((l) => {
    if (
      seen.has(l.position) ||
      !Number.isInteger(l.quantity) ||
      l.quantity < 1 ||
      l.quantity > 999 ||
      l.unitPriceMinor < 0n
    )
      throw new TotalsError("invalid_line");
    seen.add(l.position);
    const grossMinor = l.unitPriceMinor * BigInt(l.quantity);
    if (grossMinor > MAX_LINE_MINOR) throw new TotalsError("amount_out_of_range");
    const lineDiscountMinor = discountOf(grossMinor, l.discount);
    return {
      position: l.position,
      grossMinor,
      lineDiscountMinor,
      netMinor: grossMinor - lineDiscountMinor,
    };
  });
  const netSum = lines.reduce((s, l) => s + l.netMinor, 0n);
  const invoiceDiscount =
    input.invoiceDiscount === null
      ? 0n
      : netSum === 0n
        ? (() => {
            throw new TotalsError("discount_exceeds_total");
          })()
        : discountOf(netSum, input.invoiceDiscount);
  const shares = lines.map((l) => (netSum === 0n ? 0n : (invoiceDiscount * l.netMinor) / netSum));
  let rest = invoiceDiscount - shares.reduce((s, x) => s + x, 0n);
  while (rest > 0n) {
    for (let i = 0; i < lines.length && rest > 0n; i++) {
      if (lines[i]!.netMinor - shares[i]! > 0n) {
        shares[i] = shares[i]! + 1n;
        rest -= 1n;
      }
    }
  }
  if (!Number.isInteger(input.taxRateBp) || input.taxRateBp < 0 || input.taxRateBp > 10000)
    throw new TotalsError("invalid_line");
  const out = lines.map((l, i) => {
    const lineTotalMinor = l.netMinor - shares[i]!;
    return {
      ...l,
      allocatedMinor: shares[i]!,
      lineTotalMinor,
      taxMinor: roundHalfUpDiv(lineTotalMinor * BigInt(input.taxRateBp), BP),
    };
  });
  const taxMinor = out.reduce((s, l) => s + l.taxMinor, 0n);
  const totalMinor = out.reduce((s, l) => s + l.lineTotalMinor, 0n) + taxMinor;
  return {
    lines: out,
    subtotalMinor: out.reduce((s, l) => s + l.grossMinor, 0n),
    discountMinor: out.reduce((s, l) => s + l.lineDiscountMinor, 0n) + invoiceDiscount,
    taxMinor,
    totalMinor,
  };
}
```
