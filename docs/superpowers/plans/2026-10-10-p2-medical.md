# P2 — Visits, doctor notes and the medical file — Implementation Plan

> **Delivered numbering (2026-10-11).** The migrations landed as 0045 civil ID (encrypted columns),
> 0046 visits (module, catalogue, visits, notes, addenda, medical file, audit), 0047 diagnoses + ICD-10,
> 0048 prescriptions + clinic medicines, 0049 attachments and 0050 release, in one PR. Dropping the plain
> `civil_id` column is a follow-up migration. This plan's numbers (0045–0051) are the original plan and are
> kept as written below.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the shared clinical core — visits started from an arrived appointment or as walk-ins, doctor notes that lock on signing with addenda after, diagnoses (ICD-10-CM or free text), printable prescriptions, a five-section medical file, encrypted attachments, per-patient note search — with every clinical field and the civil ID encrypted, released at once behind the `medical` module flag.

**Architecture:** A new `medical` API module (visits, notes, diagnoses, prescriptions, profile, attachments, ICD-10, medicines) beside `appointments`, reading patients and appointments only through ports; AES-256-GCM field encryption with per-clinic HKDF keys in `packages/secrets`; forward-only SQL 0045–0051 with RLS and negative tests; Zod contracts frozen first so Lovable builds the whole web against the mock while the API slices land behind the flag.

**Tech Stack:** NestJS on Fastify, PostgreSQL 18 (RLS forced), Drizzle client via `@eyadex/db` (`withTenant`), Zod contracts in `packages/contracts`, Node `crypto` (AES-256-GCM, HKDF, HMAC), TanStack Start web (Lovable), vitest.

**Spec:** `docs/specs/medical-design.md` (owner decisions P2-1…P2-12, P2-F1…P2-F6, picks P2-K1…K4).

## Global Constraints

- Every clinic table: `clinic_id uuid NOT NULL`, PK `(clinic_id, id)`, RLS ENABLED + FORCED, policy `clinic_id = NULLIF(current_setting('app.clinic_id', true), '')::uuid` for USING and WITH CHECK; indexes start with `clinic_id`; every FK indexed (CLAUDE.md §5).
- New table ⇒ policy + negative isolation test in `db/tests/rls-isolation.sql` (table list + seed) in the same PR.
- IDs are UUID v7 from the application; timestamps `timestamptz` UTC.
- No hard deletes: visits are cancelled (draft only), attachments archived, medicines deactivated.
- The platform role (`eyadex_platform`) gets **no** grant on any new table; `db/tests` asserts it.
- Clinical content and the civil ID never appear in logs, errors, audit `before`/`after`, URLs or outbox payloads.
- Forward-only `db/sql`: never edit an applied file; production applies over SSH by the orchestrator, backup first, staging first.
- Arabic UI says «زيارة» and «المراجع», never «المريض»; every string through i18n (ar + en); logical CSS only; files ≤ 300 lines; Arabic JSDoc on exported `domain/**` functions and `ports/**` methods.
- Encryption: AES-256-GCM, 12-byte IV, 16-byte tag, additional data `table:column:clinic_id:row_id`, envelope `f1.<keyVersion>.<iv>.<ciphertext>.<tag>` base64url; clinic key = HKDF-SHA256(master, salt = clinic_id bytes, info = "eyadex-field", 32 bytes); civil ID index key = HKDF-SHA256(`MEDICAL_INDEX_KEY`, salt = clinic_id bytes, info = "eyadex-civil-id").
- Env: `MEDICAL_MASTER_KEY_V1` (32 bytes, base64), `MEDICAL_KEY_VERSION=1`, and a separate never-rotated `MEDICAL_INDEX_KEY` (32 bytes, base64) for the civil ID blind index (R1-7). The owner generates and pastes them into Dokploy; agents never type, read or copy a key.
- Limits: note sections ≤ 8000 chars (complaint ≤ 4000), addendum ≤ 8000, diagnosis text ≤ 500, ≤ 20 diagnoses, ≤ 30 prescription items, medical-file section ≤ 4000, attachment ≤ 20 MB of `image/jpeg|png|webp`, `application/pdf`, note search ≤ 500 newest visits of one patient.
- ICD-10-CM FY2027 from CDC/NCHS; UI shows English titles plus the CDC attribution and non-endorsement notice.

## Review amendments — Codex round 1 (binding; where a task below says otherwise, this section wins)

- **R1-1 (P0) Audit leaks to the platform.** SQL 0047 adds the medical audit entity types `visit`, `visit_addendum`, `medical_profile`, `prescription`, `attachment`, `diagnosis`, `medicine` wherever `audit_log` or its views constrain `entity_type`; every row of the first six is `category = 'patient_access'` (a CHECK like `audit_log_patient_events_are_patient_access`, extended to these types), and `platform_clinic_admin_audit` is re-created (`CREATE OR REPLACE VIEW`, same columns, owner and grant) excluding them as 0043 excluded `appointment`; `eyadex_audit_view_owner`'s policy follows. A db test connects **as `eyadex_platform`** and reads zero medical rows after a doctor writes one of each. `medicine` rows (the clinic list, not patient data) stay `administrative`.
- **R1-2 Granting medical keys.** `grant-rules.ts` gains one bounded delegation: the locked clinic-admin role may grant `visits` and `medical` keys to **other** roles without holding them; nobody else may grant a key they do not hold. `user-changes.ts` refuses changing one's own role (`role_self_change`) inside the transaction; the web mock mirrors both. Tests: the admin grants `view:medical:own` to the doctor role ⇒ ok; the admin assigns that role to itself ⇒ `role_self_change`; a doctor holding `view:medical:own` grants it to another role ⇒ `forbidden`.
- **R1-3 Bound `own` keys.** `CLINIC_BOUND` gains `view:visits:own → view:visits:clinic`, `view:medical:own → view:medical:clinic`, `update:medical:own → update:medical:clinic` (R1-2's admin delegation is the only other path); `grantFor` stops treating `view:visits:branch` as covering `view:visits:own`. The mock's `covers` mirrors it.
- **R1-4 Onboarding before release.** `identity/domain/system-roles.ts` (not `tenancy`) builds the admin from every clinic-scope key: from Task 1 on it excludes the resources `visits`, `medical`, `medicines` (their keys reach roles only at release, Task 12); the web mock's `seed-roles.ts` mirrors it. Task 1's catalogue change ships in the **same PR** as SQL 0047 (the DB catalogue must hold a key before any code names it), so Tasks 1 and 4 merge together; Lovable still gets the contracts first on `lovable` (nothing deploys from there).
- **R1-5 Civil ID compatibility phase.** Until 0046: reads use `civil_id_enc` when set, else `civil_id`; uniqueness checks both `civil_id_hmac` and plain `civil_id`; writes always set enc/hmac/last4 and `civil_id = NULL`; the backfill converts a row under the existing `patients:` advisory lock and re-reads it locked before writing. Tests: an edit during the backfill keeps the number; a create racing the backfill with the same number ⇒ exactly one wins.
- **R1-6 Dropping `civil_id`.** Three PRs: (a) PR-A = 0045 + compat code, then the backfill on staging and production; (b) PR-B = code that never names `civil_id` (store, views, tests, Drizzle mirror), deployed everywhere; (c) PR-C = 0046, whose run is preceded by the backfill command's `--verify` mode proving every `civil_id_enc` decrypts and matches its hmac and last4. 0046 is applied only after PR-B is live on that environment.
- **R1-7 Index key.** The blind index uses `MEDICAL_INDEX_KEY` (never rotated), not master V1; the API refuses to start without it; rotating `MEDICAL_MASTER_KEY_V<n>` never touches the index. Test: the HMAC is unchanged after a write-version switch.
- **R1-8 Empty values.** `open` checks the envelope has exactly five parts and, after decoding, a 12-byte IV and a 16-byte tag — not truthiness; `""` round-trips (test). Stores still write `NULL` for an empty optional section.
- **R1-9 DDL truths.** There is no modules catalogue table: 0047 replaces `clinic_features_module_check`, `permissions_module_check` and `permissions_key_check` (drop + add with the new values) before inserting the ten keys (ids after `…0c0029`); `db/tests/outbox-and-idempotency.sql` expects **51** keys; partial uniqueness uses `CREATE UNIQUE INDEX … WHERE …`, never a table constraint.
- **R1-10 `PERMISSION_KEYS`.** Task 1 adds the ten keys to the hand-written `PERMISSION_KEYS` list in catalogue order and runs `identity/domain/__tests__/appointments-catalogue.spec.ts` (and its pin to the seeded table).

Test: a custom role holding `view:appointments:own` gains nothing.

Tests send real multipart bodies: 2 files, an extra field, 20 MB + 1 byte.
- **R2-8 ICD-10 loader.** Insert the dot only when the code is longer than three characters (`F41` stays `F41`, `F411` ⇒ `F41.1`); keep header rows (billable flag `0`) in the table with `billable boolean`, but `GET /icd10` returns billable codes only and `icd10_unknown` applies to non-billable codes too; tests cover a 3-character header, a billable 3-character code and a 7-character code.
- **R2-9 Strict key decoding.** A key is accepted only if `/^[A-Za-z0-9+/]{43}=$/` matches and decoding gives 32 bytes (re-encoding equals the input); tests: a trailing `!`, a missing `=`, 31 and 33 bytes ⇒ start failure naming the variable.
- **R2-10 Print date.** `prescriptionPrintSchema` gains `startedAt: z.string().datetime()`; the print shows `signedAt ?? startedAt`; test printing a draft.

```ts
import { z } from "zod";
import { idSchema, stripInvisibleControls } from "./common.ts";
import { attachmentSchema } from "./attachments.ts";

/** P2-6: a draft is editable; signing locks it; a cancelled draft is kept, never deleted. */
export const VISIT_STATUSES = ["draft", "signed", "cancelled"] as const;
export const visitStatusSchema = z.enum(VISIT_STATUSES);
export type VisitStatus = z.infer<typeof visitStatusSchema>;

export const VISIT_CANCEL_REASONS = ["opened_by_mistake", "patient_left", "other"] as const;
export const visitCancelReasonSchema = z.enum(VISIT_CANCEL_REASONS);

const clinicalText = (max: number) =>
  z
    .string()
    .transform(stripInvisibleControls)
    .pipe(z.string().trim().max(max, "validation.tooLong"));
const required = (max: number) => clinicalText(max).pipe(z.string().min(1, "validation.required"));

/** `POST /v1/visits` (Idempotency-Key): from an arrived appointment, or a walk-in (P2-2). */
export const visitStartSchema = z.union([
  z.object({ appointmentId: idSchema }).strict(),
  z.object({ patientId: idSchema, branchId: idSchema }).strict(),
]);
export type VisitStartInput = z.infer<typeof visitStartSchema>;

/** `PUT /v1/visits/:id/note` — draft only, the visit's provider only (P2-3). */
export const visitNoteInputSchema = z
  .object({
    complaint: clinicalText(4000).nullable(),
    examination: clinicalText(8000).nullable(),
    assessment: clinicalText(8000).nullable(),
    plan: clinicalText(8000).nullable(),
  })
  .strict();
export type VisitNoteInput = z.infer<typeof visitNoteInputSchema>;

/** ICD-10-CM code shape: letter, digit, letter-or-digit, optional dot and up to four more. */
export const icd10CodeSchema = z
```

```ts
// field-cipher.ts
import { createCipheriv, createDecipheriv, hkdfSync, randomBytes } from "node:crypto";

const ALGORITHM = "aes-256-gcm";
const TAG_BYTES = 16;
const PREFIX = "f1";

export type FieldRef = { readonly table: string; readonly column: string; readonly rowId: string };

/**
 * بيشفّر حقل طبي أو الرقم المدني بمفتاح العيادة (HKDF من المفتاح الرئيسي)، ومربوط بالجدول والعمود والصف
 * والعيادة، عشان القيمة المنسوخة لمكان تاني ماتتفتحش (ADR-0028).
 */
export class FieldCipher {
  readonly #keys: ReadonlyMap<number, Buffer>;
  readonly #writeVersion: number;

  constructor(keys: ReadonlyMap<number, Buffer>, writeVersion: number) {
    for (const [v, key] of keys)
      if (key.length !== 32)
        throw new TypeError(`MEDICAL_MASTER_KEY_V${v} must be 32 bytes, base64-encoded`);
    if (!keys.has(writeVersion))
      throw new TypeError(`MEDICAL_MASTER_KEY_V${writeVersion} is missing`);
    this.#keys = keys;
    this.#writeVersion = writeVersion;
  }

  /** @returns مفتاح العيادة لإصدار معيّن، أو لاستخدام معيّن (`info`) */
  derive(clinicId: string, version: number, info: string): Buffer {
    const master = this.#keys.get(version);
    if (master === undefined) throw new Error("unknown key version");
    return Buffer.from(hkdfSync("sha256", master, Buffer.from(clinicId, "utf8"), info, 32));
  }

  get writeVersion(): number {
    return this.#writeVersion;
  }

  /** @returns `f1.<version>.<iv>.<ciphertext>.<tag>` */
  seal(clinicId: string, ref: FieldRef, plain: string): string {
    const iv = randomBytes(12);
    const cipher = createCipheriv(
      ALGORITHM,
      this.derive(clinicId, this.#writeVersion, "eyadex-field"),
      iv,
    );
    cipher.setAAD(aad(clinicId, ref));
    const body = Buffer.concat([cipher.update(plain, "utf8"), cipher.final()]);
    return [
      PREFIX,
      String(this.#writeVersion),
      iv.toString("base64url"),
      body.toString("base64url"),
      cipher.getAuthTag().toString("base64url"),
    ].join(".");
  }

  /** بيفتح القيمة؛ أي تلاعب أو مكان غلط بيرمي خطأ من غير ما يكشف أي حاجة. */
  open(clinicId: string, ref: FieldRef, envelope: string): string {
    const parts = envelope.split(".");
    if (parts.length !== 5 || parts[0] !== PREFIX) throw new Error("malformed envelope");
    const [, version, iv, body, tag] = parts as [string, string, string, string, string];
    if (
      Buffer.from(iv, "base64url").length !== 12 ||
      Buffer.from(tag, "base64url").length !== TAG_BYTES
    ) {
      throw new Error("malformed envelope");
    }
    const decipher = createDecipheriv(
      ALGORITHM,
      this.derive(clinicId, Number(version), "eyadex-field"),
      Buffer.from(iv, "base64url"),
      { authTagLength: TAG_BYTES },
    );
    decipher.setAAD(aad(clinicId, ref));
    decipher.setAuthTag(Buffer.from(tag, "base64url"));
    return Buffer.concat([
      decipher.update(Buffer.from(body, "base64url")),
      decipher.final(),
    ]).toString("utf8");
  }
}

const aad = (clinicId: string, ref: FieldRef) =>
  Buffer.from(`${ref.table}:${ref.column}:${clinicId}:${ref.rowId}`, "utf8");

/** بيبني الـ cipher من متغيرات البيئة، ويفشل وقت التشغيل لو مفتاح ناقص أو غلط. */
export function fieldCipherFromEnv(env: Record<string, string | undefined>): FieldCipher {
  const writeVersion = Number(env["MEDICAL_KEY_VERSION"] ?? "1");
  const keys = new Map<number, Buffer>();
  for (const [name, value] of Object.entries(env)) {
    const m = /^MEDICAL_MASTER_KEY_V(\d+)$/.exec(name);
    if (m && value) keys.set(Number(m[1]), strictKey(name, value));
  }
  if (!keys.has(writeVersion))
    throw new TypeError(`MEDICAL_MASTER_KEY_V${writeVersion} is missing`);
  return new FieldCipher(keys, writeVersion);
}

/** يقبل المفتاح بس لو Base64 سليم بالظبط و32 بايت (R2-9)، عشان مفتاح متقصّ أو فيه حرف زيادة مايعدّيش. */
export function strictKey(name: string, value: string): Buffer {
  const key = Buffer.from(value, "base64");
  if (
    !/^[A-Za-z0-9+/]{43}=$/.test(value) ||
    key.length !== 32 ||
    key.toString("base64") !== value
  ) {
    throw new TypeError(`${name} must be 32 bytes, base64-encoded`);
  }
  return key;
}
```

```ts
}

}
```
