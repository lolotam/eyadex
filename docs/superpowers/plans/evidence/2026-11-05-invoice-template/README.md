# قالب فاتورة صناعي متعدد الصفحات — قيد التحقق

هذه دفعة بحث واختبار، وليست راسم التطبيق. كل البيانات صناعية؛ لا تستخدم الحزمة مع فواتير أو أسماء
حقيقية. `UnavailableInvoicePdf` ما زال راسم التشغيل، وأعلام قبول الفاتورة والتفعيل تظل `false`.

## النطاق

- قالب A4 به شعار صناعي، اسما العيادة، الفرع والعنوان والهاتف ورقم التسجيل، رقم الفاتورة وتاريخها
  وحالتها واسم عرض المراجع، جدول البنود، الخصومات وأسبابها، الضريبة والإجماليات والعملة والنسخة.
- القالب يستقبل مبالغ منسقة مسبقًا؛ لا يحسب الأموال. أمثلة E1–E5 من `finance-design.md` §8b.1
  منسوخة في fixtures بأرقامها المخزنة، مع اختبار منفصل لفاتورة 50 بندًا والإلغاء والعملات الست.
- كل كلمة مرتبطة بمعرّف اصطناعي في annotation ينشئه Typst. الربط يقرأ شجرة البنية وMCIDs، ويحفظ
  أوامر الرسم الأصلية داخل Type 3 glyph ثم Form XObject. الـForm يفصل حالة استخراج كل كلمة عن
  سابقتها؛ بدونه انفصلت شدة `عَلِيّ` في النص متعدد الكلمات.
- رؤوس الجداول المتكررة وشريط الإلغاء والتذييل تأتي من Typst كـartifacts. تربط عبر annotations
  ومواضع أوامر النص بعد تطبيق مصفوفات الرسم. الربط المفقود أو الملتبس يرفض الملف. تحذف annotations
  الاصطناعية قبل الإخراج، وتبقى حدود Artifact؛ تحدث مراجع ParentTree للمحتوى المنقول.
- ترميز ToUnicode وترميز ActualText منفصلان. للكلمة العربية يسبق كل محرف في ToUnicode ثلاثة
  محارف LRM غير مرئية، لإبقاء اتجاه pdf.js المثبت LTR وعزل ترتيب المحارف الأصلي؛ ActualText يضع
  LRM على جانبي كل محرف لـPoppler. تبقى محارف التشكيل والأرقام وعلامات الترقيم الأصلية دون تغيير.
  هذه معالجة تجريبية خاصة بالمستخرجين المثبتين، وليست تنفيذًا عامًا لخوارزمية Unicode bidi.
- التحقق يسبق أي مسار للكلمات العربية أو غير العربية: ترفض محارف التحكم الأصلية والسكربتات غير
  المدعومة. يرفض المرشح أيضًا `<` و`>` داخل كلمة عربية، وLatin compatibility ligatures؛ أظهر
  الاختبار أن pdf.js يحذف الأولى أو يطبع الثانية بشكل مختلف. هذا نقص باقٍ، وليس قبولًا كاملًا للنص.
- معرّفات `urn:e:` القصيرة تحمل معرّف الكلمة وموضع ظهورها، حتى يرفض الاختبار تكرار الحقل نفسه
  مرتين في الصفحة. إحداثيات المعرف مقربة إلى 0.001 نقطة؛ فحص مستطيلات النص يستعمل القيم الأصلية.
  تشارك المقاطع المتطابقة، وتضغط object streams في qpdf، دون إعادة رسم الصور أو تصغيرها.

## الفحوص

`run.mjs` يرسم ويصحح النماذج، ويتحقق من:

1. جميع معرّفات الكلمات المخصصة، وعدد ظهور الحقول المتكررة، وترتيب الحقول من المصدر قبل التصحيح.
2. كل نص ظاهر في نموذج الاختبار، بالترتيب في pdf.js وpdftotext، مع أرقام الصفحات وشريط الإلغاء
   وسببه وتاريخه لكل صفحة في الأداتين. التطبيع يحذف محارف التحكم في الاتجاه ويضغط المسافات فقط.
3. عدد الصفحات وأبعاد A4، وجود شجرة البنية التي يقرأها pdf.js، وعدم بقاء روابط الربط الاصطناعية.
   وجود الشجرة ليس شهادة PDF/UA ولا مراجعة كاملة لإتاحة الاستخدام.
4. `qpdf --check`، وحد 5 MB للملف الوسيط والنهائي، وتساوي مصفوفة RGBA لكل صفحة قبل/بعد عند 96 DPI،
   مع إعادة فحص الصفحة الأولى عند 144 DPI.
5. رفض حذف حقل ذي قيمة مكررة، ورفض محارف تغيير الاتجاه بدل نشر نتيجة تبدو صحيحة.

تشمل MIXED عدد 24 كلمة مثل `مبنى12` و`مبنى١٢` و`مُحَمَّد-test` و`(مبنى12)`، والعملات والنسب
والأقواس وعلامات الترقيم. لا يثبت هذا قبول كل سلسلة Unicode ممكنة.

## إعادة التشغيل

من جذر المستودع، يبني Dockerfile البحث السابق مع هذه الملفات ويشغل الحزم الثلاث بالتتابع:

```powershell
$invoiceProofOutput = Join-Path ([IO.Path]::GetTempPath()) 'eyadex-invoice-template-proof'
New-Item -ItemType Directory -Force $invoiceProofOutput | Out-Null
docker build -f docs/superpowers/plans/evidence/2026-11-04-pdf-reproduction/Dockerfile -t eyadex-pdf-invoice:proof .
docker run --rm --network none --read-only --ulimit core=0 --mount "type=bind,source=$invoiceProofOutput,target=/out" eyadex-pdf-invoice:proof
```

المخرجات PDF وPNG وJSON صناعية فقط. مهلة rasterizer في الاختبار ليست مهلة راسم الإنتاج؛ حدود
الـ5 ثوان والتزامن والتنظيف وحماية كل العمليات ما زالت تحتاج تنفيذًا واختبارات مستقلة.

## النتيجة وحدود القبول

هذا دليل تشغيل للعينة المحددة، وليس شهادة تغطي جميع المدخلات المسموحة. مراجعة لاحقة حددت فحوصًا
ناقصة قبل قبول الراسم: دمج أقصى المحتوى مع شعار قريب من حد 1 MB، مطابقة كامل الرسم بالكلمة
المتوقعة، والتحقق من غياب النص المكرر أو الزائد بدل الاكتفاء بوجود النص المتوقع وترتيبه. تبقى هذه
متطلبات مفتوحة؛ الفحوص الحالية لا تثبتها.

للمقاطع المدعومة من المولد المثبت، فحص ترميز الرسم يرفض الآن أي كود مستخدم بلا ترجمة أو بترجمة
فارغة، وأي سلسلة ناقصة أو معطوبة.
الرفض لكل سلسلة على حدة؛ لا يجمع جزأين ناقصين ليشكّل كودًا مقبولًا. هذا يغلق قبول الرموز المجهولة،
ولا يثبت وحده تطابق جميع حروف الرسم وترتيبها مع الكلمة المتوقعة.

ترتيب الصفحات يأتي من شجرة `/Pages` في Catalog، وليس ترتيب الكائنات. ترتيب حقول الرأس والتذييل
المتكررة يأتي من المصدر، ويُفحص كمتتالية كاملة لكل دور في كل صفحة، في الربط وفي المستخرجين.
اختبارات التحوير تبدّل عمودين كاملين وحقلي تذييل، وتعكس ترتيب تخزين كائنات PDF. لغتا الرأس الآن
في خليتين منفصلتين: الإنجليزية بمحاذاة اليسار والعربية بمحاذاة اليمين.

أحدث تشغيل كامل نجح لـ16 نموذج فاتورة و31 صفحة بعد تصحيح الرأس وترتيب الصفحات؛ الأرقام وبصمة
الناتج والسجلات السابقة في [سجل التشغيل](results.md). العينة القصوى المصححة 13 صفحة، مع رأس جدول
متكرر وترقيم الصفحات والنص كاملًا.
أسباب الخصم العربية غير المنقطعة ذات 300 محرف، بتشكيل ودونه، مغطاة. كل وجهة ToUnicode محدودة
بـ512 بايت؛ الاختبار يفحص الحد في الملف الناتج، وليس طول قائمة المحارف فقط.

- اعتمد المالك في 2026-11-05 زيادة الصفحات عند الحاجة بدل حد الثلاث صفحات، مع الإبقاء على النص
  كاملًا ومقاسات الخط. حدثت مواصفة PDF، وأضيف MAXCONTENT: 50 بندًا بأوصاف 200 حرف وأسباب 300 حرف.
- نقص الأقواس الزاوية والـLatin compatibility ligatures المذكور أعلاه يحتاج حلًا دون حذف النص.
  قياسات صناديق النص والتحديد التفاعلي تحتاج التحقق قبل التوصيل؛ تطابق الرسم لا يثبت صحة تخطيط
  الأصل وحده.
- أحدث قياس MAXCONTENT: 4,990,378 بايت للوسيط و2,289,152 بايت للنهائي. أخذ Typst
  وحده 10,812 ms؛ التشغيل الكامل الأول سجل 23,482 ms على الجهاز المشترك. كلاهما
  يتجاوز مهلة الإنتاج البالغة 5 ثوان؛ هذه ليست قياسات p95 للإنتاج. مهلة الاختبار الموسعة لا تغيّر
  مهلة الإنتاج.
- يلزم تثبيت نتيجة تشغيل المرشح ومراجعة الكود. هذه الحزمة لا تثبت زمن staging أو صلاحيات API
  أو سباقات الفاتورة والرابط أو حماية الانهيارات أو جاهزية نشر.
