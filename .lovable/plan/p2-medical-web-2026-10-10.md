# P2 — web (Lovable)

Branch `lovable`, mock first. Source: `docs/superpowers/plans/2026-10-10-p2-medical.md` Task 13.

Read `CLAUDE.md` fully, then `docs/specs/medical-design.md` §1, §2, §5, §7. The contracts are frozen; build only against them:
`packages/contracts/src/visits.ts`, `medical-profile.ts`, `medicines.ts`, `icd10.ts`, `attachments.ts`, and the additions in `permissions.ts` (resources `visits`, `medical`, `medicines`), `onboarding.ts` (module `medical`), `common.ts` (new error codes), `organization.ts` and `audit.ts` (medical audit entities and actions), `platform.ts` (`defaultModuleMedical`). Never edit `packages/contracts`, `apps/api`, `db/`, `roadmap.md` or `docs/adr`; if a contract looks wrong, stop and say so.

1. **Client** `apps/web/src/shared/api/medical-client.ts` — `MedicalApi`:
   `listVisits(persona, patientId, { cursor })`, `searchVisits(persona, patientId, { q, cursor })` (POST body), `walkInBranches(persona)`, `walkInCandidates(persona, { branchId, q })` (POST body), `startVisit(persona, input, idempotencyKey)`, `getVisit(persona, visitId)`, `saveNote(persona, visitId, input)`, `saveDiagnoses(persona, visitId, input)`, `savePrescription(persona, visitId, input)`, `signVisit(persona, visitId)`, `cancelVisit(persona, visitId, input)`, `addAddendum(persona, visitId, input)`, `getMedicalProfile(persona, patientId)`, `saveMedicalProfile(persona, patientId, input)`, `searchIcd10(persona, q)`, `listMedicines(persona)`, `createMedicine(persona, input, idempotencyKey)`, `updateMedicine(persona, id, input)`, `deactivateMedicine(persona, id)`, `reactivateMedicine(persona, id)`, `listAttachments(persona, patientId, { visitId })`, `uploadAttachment(persona, patientId, file, visitId)` (multipart: `file` + optional `visitId`), `downloadAttachment(persona, attachmentId): Promise<Blob>`, `archiveAttachment(persona, attachmentId)`, `getPrescriptionPrint(persona, visitId)`.
   HTTP adapter: the routes of spec §5, answers parsed with the schemas, errors through `http-errors.ts` (codes already added). No clinical text, patient name or search text ever goes into a URL.
2. **Mock** `apps/web/src/shared/api/mock/mock-medical-*.ts` (each ≤ 300 lines), same rules as the API: module flag; keys and scopes; `own` = an appointment that is not cancelled **or any** visit with the caller; only the visit's provider writes; draft vs signed vs cancelled; one live visit per appointment (`visit_exists` with `details.visitId`); the appointment must be `arrived` (`appointment_not_arrived`); signing needs a non-empty note section or diagnosis (`visit_empty`); addenda only on signed (`visit_not_signed`); edits on signed ⇒ `visit_signed`; removed diagnoses/prescription items are archived, never shown; attachments ≤ 20 MB of jpeg/png/webp/pdf and belong to the same patient as their visit (`attachment_patient_mismatch`); walk-in candidates only active files of the branch, max 20, name + file number. Mock audit rows use the new entities/actions, `patient_access` for everything except medicines, and carry field **names** only — never clinical text, codes, medicine names, queries or civil IDs (they go through the same scrub as PR #66). The mock stores plaintext (demo only).
3. **Seeds and roles**: `seed-roles.ts` — doctor: `view:visits:own`, `create:visits:own`, `view:medical:own`, `update:medical:own`, `view:medicines:clinic`; receptionist: + `view:visits:branch`; locked admin: every clinic-scope key **except** the `medical` resource keys (it gets `visits` and `medicines`). Grant rules in the mock: the locked admin may grant `visits`/`medical` keys to other roles without holding them; nobody else grants a key they lack; `own` medical/visits keys are clinic-bound; nobody changes their own role (`role_self_change`). Seed a few visits (draft and signed, with addenda, diagnoses of both kinds, a prescription) for the doctor persona's patients, using made-up names and no real phone or civil ID.
4. **Roles screen**: labels ar/en for the three resources; a single-scope row uses the definition's scope (so `create:visits:own` is saved as `own`).
5. **Patient file tabs**: Overview (today's) · Medical file (five sections; edit with `update:medical:*`) · Visits (list newest first with preview when allowed; search box with `view:medical:*` calling `searchVisits`) · Attachments (upload, list, open via `downloadAttachment` + `URL.createObjectURL`, archive). Each tab only with its key.
6. **Visits page** `/clinic/visits` (nav item with `create:visits:own`): "New walk-in visit" — pick a branch from `walkInBranches`, search with `walkInCandidates`, pick, `startVisit({ patientId, branchId })`, open the visit.
7. **Visit page** `/clinic/visits/$visitId` (reload-safe from `getVisit` alone; header shows `patient.fullName`, `#fileNumber`, branch, provider, status): four note sections with debounced autosave on the draft; diagnoses table (per row a switch ICD-10 / free text; ICD-10 search shows `code — English title`, footer: "ICD-10-CM: CDC/NCHS. Use does not imply endorsement."); prescription items (medicine combobox from the clinic list or typed, dose, frequency, duration, note); visit attachments; **Sign** (confirm: "After signing the note cannot be edited; corrections are added as addenda.") · **Cancel draft** (reason + note) · **Add addendum** on signed · **Print prescription** (print stylesheet; clinic ar/en, branch, patient name + file number, provider, `signedAt ?? startedAt`, items; RTL in Arabic). Buttons follow `can` (UX only — the mock refuses too).
8. **Branch day and today's queue**: "Start visit" on an `arrived` appointment when the caller is its provider and holds `create:visits:own`; on `visit_exists` open `details.visitId`.
9. **Settings → Medicines** tab (`view/update:medicines:clinic`); the Settings nav gate and first-tab logic include it.
10. **Platform settings**: the `defaultModuleMedical` switch shown; the mock refuses turning it on before release (`validation`, `details.field = "defaultModuleMedical"`).
11. **Audit screen**: labels for the new entities and actions; details show field names only.
12. **Strings**: «زيارة»، «ملاحظات الطبيب»، «الملف الطبي»، «التشخيص»، «الروشتة»، «المرفقات»، «اعتماد»، «ملحق»، «زيارة مباشرة»; never «المريض». Every string in `ar-*.ts` and `en-*.ts`.
13. **Tests (vitest)**: mock rules above (one test per error code); tabs and buttons by key; draft vs signed vs cancelled controls; ICD-10/free-text switch; print view renders items and the right date; walk-in flow; roles screen saves `create:visits:own`; ar/en key parity; no clinical text, query or medicine name in mock audit rows or in any URL the HTTP adapter builds.
14. **Hard rules**: logical CSS only; shadcn + lucide; react-hook-form + Zod; TanStack Query through the ApiClient; ≤ 300 lines per file, one component per file; no Lovable Cloud/Supabase; `TODO(spec)` + tell me instead of guessing.
