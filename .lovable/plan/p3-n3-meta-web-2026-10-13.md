## 2. WhatsApp tab → WhatsApp Business card

**Primary action: «ربط واتساب للأعمال» / "Connect WhatsApp Business".**

1. Call `GET /v1/clinic/whatsapp/signup-config`. On 404 `unavailable`, hide this button and show only the
   manual form.
2. Load `https://connect.facebook.net/en_US/sdk.js` once, only on this tab. Then call
   `FB.init({ appId, version: graphVersion, xfbml: false, cookie: false })`.
3. On click, call `FB.login(callback, { config_id: configId, response_type: "code",
override_default_response_type: true, extras: { feature: "whatsapp_embedded_signup", sessionInfoVersion: "3",
featureType: "whatsapp_business_app_onboarding", setup: {} } })`.
   - The callback must be synchronous. Start the async work inside it without awaiting.
4. Listen to `window` `message` events.
   - Parse `event.origin` as a URL and accept only a hostname equal to `facebook.com` or ending with
     `.facebook.com`; ignore all other origins, including `evilfacebook.com`.
   - Parse `event.data` (a string or an object). Keep only `type === "WA_EMBEDDED_SIGNUP"`.
   - Collect `waba_id` and `phone_number_id`, including when they are nested under `data`.
   - `CANCEL` or `ERROR`: close quietly with «تم إلغاء الربط» / "Linking was cancelled".
5. After the callback returns `authResponse.code`, wait up to 2.5 s for the ids. Then call
   `POST /v1/clinic/whatsapp/embedded-signup` with `{ code, wabaId, phoneNumberId }`.
   - No code means the window was closed: show nothing.
   - A code but no ids: «لم يكتمل اختيار الرقم في نافذة Meta — حاول مرة أخرى» / "The number was not chosen in
     Meta's window — try again".
6. Refusals, shown inline:

   | Code                    | Arabic                              | English                                   |
   | ----------------------- | ----------------------------------- | ----------------------------------------- |
   | `meta_code_invalid`     | «انتهت صلاحية الربط، حاول مرة أخرى» | "The link expired, try again"             |
   | `meta_two_step_enabled` | the two-step text above             | the two-step text above                   |
   | `number_in_use`         | «هذا الرقم مربوط بعيادة أخرى»       | "This number is linked to another clinic" |

   503 shows the existing unavailable copy.

7. On success, the card shows «متصل …1234». Then show the template fields for that number, with the same
   templates as today.
8. Keep the current manual form, under a collapsible «متقدّم» / "Advanced" with the existing fields. The
   manual save also shows `number_in_use` under «معرّف رقم الهاتف».
9. Fix the stale hint `whatsapp.business.dialogHint`: the ids are now pre-filled, and only the token is
   never shown again.

## 3. Mock

- `signup-config` answers fixed demo ids.
- The mock does not load the real SDK. Instead it simulates the flow:
  - a «تجربة الربط» button in mock mode calls the same `embeddedSignup` client method with a demo code;
  - code `"cancel"` = nothing happens;
  - code `"two_step"` = `meta_two_step_enabled`;
  - code `"used"` = `number_in_use`;
  - anything else connects with `phoneLast4: "0000"`.
- History: sent WhatsApp rows get `deliveredAt` after 3 s and `readAt` after 6 s, both deterministic in
  tests with fake timers. `whatsapp_two_step` is used when the patient's phone ends in `9`.
